# Data Provenance

Every table in this project carries a `source_type`. These are the only four values that exist, and this is what each one actually means here — checked against the real access requirements of each source, not assumed.

## historical_broadcast — SoccerNet action-spotting labels

**What it is:** Real event annotations (goal, card, substitution, and 14 other action classes) for real, played, broadcast football matches, with real in-match timestamps (half + MM:SS). Published by the SoccerNet research consortium.

**What it is not:** Live. These are archival broadcasts, some years old. Nothing in this project ever calls this data "live" — it is labeled Historical Broadcast Data everywhere it appears, including in the agent's own responses.

**Access, verified directly:** The label files (`Labels-v2.json`) are public with zero registration, zero password, zero NDA — confirmed against SoccerNet's own PyPI package documentation. The raw broadcast *video* files are separately gated behind a Hugging Face account + NDA form; this project does not touch the video files, only the label/annotation layer, so nothing here required signing anything.

**Why this is enough:** The DAZN JD's "playback data / OTT / broadcast" ask is about being able to model, query, and reason over structured broadcast event data — not about having decoded video frames. Real timestamped event data at match-and-half granularity supports every SQL/BI/agent capability this project demonstrates.

## current_delayed — football-data.org free tier

**What it is:** Real fixtures, results, and league tables across 12 real competitions (Premier League, La Liga, Champions League, World Cup, etc.), refreshed as real matches are actually played.

**What it is explicitly not:** Live/in-play scores. football-data.org's free tier delays scores and schedules; true real-time livescore feeds are a paid tier we are not using. Calling this "live" would be a fabrication the whole rest of this project is built to avoid — so it is labeled **Current/Delayed Source Data**, never "live," anywhere it surfaces (schema, BI, agent responses).

**Access:** Free API token via email signup, no payment, no approval wait — the user does this themselves (same pattern as the earlier Supabase signup).

## real_research — LIVE-APV video-QoE dataset (pending)

**What it is, once obtained:** 367 real videos across 97 real content pieces with over 14,000 real human subjective-quality opinion scores, from UT Austin's LIVE lab.

**Access, verified directly:** Requires submitting a Google Form; the dataset password and link are then emailed — timing outside our control, and not something a cloud sandbox can do on the user's behalf. The user submits this form themselves, in parallel with everything else being built.

**Until it arrives:** No row in this project claims to be LIVE-APV data. The QoE layer runs on `synthetic_derived` data until the real dataset lands, at which point the same schema swaps to ingest the real MOS scores — no rework, just a real source replacing a labeled stand-in.

## synthetic_derived — generated streaming telemetry

**What it is:** Playback/QoE-style records (buffering, startup delay, session duration) generated by us to exercise the analytical architecture, because real DAZN/Netflix/any-streamer session-level telemetry is proprietary and not published anywhere, by anyone, ever — there is no legitimate way to obtain it publicly, and pretending otherwise would be the fabrication this whole document exists to prevent.

**Rule enforced in schema, not just prose:** `raw.qoe_observations.generation_method` is required (non-null) whenever `source_type = 'synthetic_derived'`. A synthetic row with no documented generation method is treated as a data-quality failure by the validation layer, not just a style nit.

---

Every number this platform's agent or dashboards produce traces back to exactly one of the four rows above. If a question can't be answered from real or honestly-labeled-synthetic data, the correct answer is "I don't have the data to answer that reliably" — not a plausible-sounding guess.
